# propgen — генератор игровых пропов из фото

Фото предмета → чистый «студийный» фронт → 3D → лоу-поли в духе Half-Life 2 (≈1–3 тыс. треугольников, текстура
512–1024, normal map, AO), выгрузка в GLB. Всё считается локально: ComfyUI (генерация) + Blender (лоу-поли и запекание)
+ небольшой веб-интерфейс.

![интерфейс](shots/1-interface.png)

## Что нужно

- Windows, видеокарта **NVIDIA от 8 ГБ** (на 12–16 ГБ заметно быстрее), оперативка от 32 ГБ, ~35 ГБ на диске под модели.
- [ComfyUI](https://www.comfy.org/) свежей версии (Desktop, portable или git) + нода [ComfyUI-GGUF](https://github.com/city96/ComfyUI-GGUF).
- [Blender](https://www.blender.org/download/) 4.2 или новее.
- Python 3.10–3.12.
- Для перевода заметок (по желанию): ключ OpenAI **или** бесплатный [LM Studio](https://lmstudio.ai) с локальной моделью.

## Установка

Проще всего — попросить Claude Code: в проекте есть скилл `propgen-setup` (`.claude/skills/propgen-setup/SKILL.md`),
он найдёт ComfyUI, поставит недостающее, скачает модели и проверит всё прогоном. Скажи ему «установи propgen».

Вручную:
1. Запусти ComfyUI.
2. `setup.cmd` — создаст `.venv`, поставит зависимости и покажет проверку системы.
3. `start.cmd` — откроется http://127.0.0.1:8795. Если чего-то не хватает, сразу откроются **Настройки** (шестерёнка
   вверху справа): там проверка системы с кнопками «Скачать» для моделей (~32 ГБ основное), адрес ComfyUI, путь к Blender,
   ключ OpenAI или LM Studio.
4. Проверка целиком: `.venv\Scripts\python tools\smoke.py` — тестовый проп из `examples\kettle.png` проходит все шаги.

Всё то же из консоли: `.venv\Scripts\python tools\doctor.py` (отчёт), `tools\doctor.py download --group core` (модели),
`--group hdri` (панорамы 4k для фона просмотрщика). Настройки лежат в `config.json` (создаётся сам, в git не попадает).

## Как пользоваться

1. **+ Новый** (или просто брось фото в окно / вставь скриншот `Ctrl+V`) — одно или несколько фото предмета.
2. **Кадр** — обведи предмет рамкой (сохраняется сама; ручки по краям, направляющие у курсора). Оставь запас по краям —
   то, что касается края кадра, генератор может потерять.
3. **Заметка** — своими словами, можно по-русски: что это, что написано и что значит. Кнопка «✨ Из заметки» соберёт
   английский промпт (полный перевод + детали с кадра); или он соберётся сам при запуске.
4. **▶ Всё сразу** — чистый фронт → 3D → лоу-поли. Каждый шаг можно перезапустить отдельно (▶ у шага), остановить (■),
   посмотреть лог (≡). Вид можно перегенерировать (↻), заменить своим фото (⤒), открыть крупно (клик).
5. **Модель** — просмотр лоу-/хай-поли с сеткой, ракурсы кубом, фон-панорама. Справа: бюджет треугольников, жёсткие рёбра,
   размер текстуры, поворот (генератор сам решает, где у предмета перед), выгрузка GLB и карт.

Пропы хранятся в `work/props/<id>/` (`meta.json`, `photos/`, `crop.png`, `views/`, `mesh/`, `lo/`, `logs/`).

## Конвейер

| Шаг | Чем | Время на RTX 5060 8 ГБ |
|---|---|---|
| Промпт | `tools/llm_openai.py`: заметка → полный перевод + детали с кадра; gpt-4.1-mini, один запрос, кадр 512 px `detail: low`, кэш, учёт расхода в `work/llm_usage.jsonl`, дневной лимит. Без ключа — `tools/llm.py` (Gemma-3-4B в LM Studio, на время ответа забирает видеокарту у ComfyUI) | ~2 с, ~$0.0003 · локально ~10 с |
| Фронт / виды | `tools/views.py`: Qwen-Image-Edit-2511 Q4 GGUF + Lightning 4 шага, 768 px; для режима «4 вида» — LoRA Multiple-Angles | ~70 с на вид (первый после запуска ComfyUI ~3,5 мин) |
| 3D | `tools/mesh.py`: TRELLIS.2 (или Pixal3D) по одному изображению, Pixal3D multiview по 4 видам → хай-поли 150k, текстура 2048 | ~3 мин |
| Лоу-поли | `tools/lowpoly.py` (Blender) + `tools/solidify.py`: сплошное тело → квадрик-декимация MeshLab → жёсткие рёбра → Smart UV → запекание цвета, нормалей и AO (Cycles) → подгонка цвета `tools/colormatch.py` | ~20 с |

Лучше всего работает «одно изображение → чистый фронт → TRELLIS.2». Режим «4 вида» хуже: развороты LoRA скорее ¾, чем
ровно 90°, и детали в видах расходятся. Он полезен со своими настоящими фото сбоку и сзади (⤒ в карточке вида).

### Почему лоу-поли так устроен

Сетка TRELLIS/Pixal3D после `RemeshMesh` — тонкая двойная оболочка с дырами, внутренними пузырями и сотнями шумовых
туннелей. На ней всё ломается: `DecimateMesh` в ComfyUI схлопывает форму до десятков треугольников, Decimate в Blender
оставляет иглы, MeshLab с сохранением топологии застревает на ~4k, а без него стенки прорастают друг в друга.
Рабочий путь — `solidify.py`: воксели оболочки → заливка всего, что недостижимо снаружи (+ заливка горизонтальных
срезов — закрывает предметы без дна) → поле «расстояние до исходной сетки минус t» (KD-дерево, точность меньше вокселя)
→ marching cubes → одна замкнутая поверхность → декимация.

Нормали и AO запекаются не с хай-поли генератора, а с этого гладкого тела: хай-поли несёт полосы воксельной решётки
генератора и дрожь ремеша, в normal map это давало «кашу» мелких граней. Цвет печётся с хай-поли.

## Если что-то не так

- **Вид генерируется десятки минут** (в строке состояния минуты на шаге выборки, «⚠ без событий»): ComfyUI вынес часть
  памяти в «общую» GPU-память Windows. Перезапусти ComfyUI. Профилактика — панель NVIDIA → «Управление параметрами 3D» →
  программа = python.exe ComfyUI → «CUDA — политика резервной системной памяти» → «Предпочитать отсутствие».
- **Шаг упал** — лог: ≡ у шага или `work/props/<id>/logs/<шаг>.log`.
- **Что-то не найдено** — шестерёнка «Настройки» → «Проверка системы» подскажет, что именно и как поправить.

## Устройство

- `server.py` — FastAPI: пропы, очередь задач (видеокарта одна — шаги по одному), настройки, проверка системы.
- `web/` — интерфейс (без сборки, three.js с CDN), `web/hdri/` — панорамы Poly Haven (CC0).
- `tools/` — скрипты шагов (работают и сами, параметры — в шапке файлов), `config.py` — настройки, `doctor.py` — проверка
  и докачка, `comfywatch.py` — живой прогресс ComfyUI, `smoke.py` — проверка установки.
- `.claude/skills/propgen-setup/` — инструкция для агента по установке.
